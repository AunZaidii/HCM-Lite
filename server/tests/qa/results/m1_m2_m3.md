# QA results — M1, M2, M3 (HCM_Lite_Test_Plan.md §3–§5)

All data was created through the API, and time rules used the frozen test clock (`ctx.at`, Karachi time). No application code was changed.

Files: `tests/qa/m1_auth.test.js`, `tests/qa/m2_firstrun.test.js`, `tests/qa/m2_setup.test.js`, `tests/qa/m3_employees.test.js`.

> Login rate limit (10 per minute per IP) is a real security control. These tests send a different `X-Forwarded-For` client IP per login so the suite isn't throttled. The app trusts one proxy hop.

## Bugs

1. **Out-of-range office time crashes the settings API (500)** — M2-10 · Medium
   - Steps: as Admin, `PUT /api/settings {"officeStart":"25:99"}`.
   - Expected: 400 with a field message. Actual: 500 (Postgres `DateTimeParseError`).
   - Cause: the time regex only checks the shape. `server/src/modules/org.routes.js:13` uses `/^\d{2}:\d{2}(:\d{2})?$/`, and the setup wizard's `server/src/modules/auth.routes.js:17` has the same weakness.
2. **Employee can read Admin setup lookup lists** — M2-20 · Low
   - Steps: as Employee, `GET /api/departments`, `/api/designations`, `/api/holidays`.
   - Expected: 403 (checklist item 04 gives Employee no access). Actual: 200 with full lists.
   - Cause: `server/src/modules/org.routes.js` `crud()` defaults `readRoles` to include `employee`. Reading leave types is legitimately needed for the leave form.
3. **Deactivated employee is still counted in headcount** — M3-10 · Medium
   - Steps: Admin deactivates an employee login (`POST /users/:id/deactivate`), then open `GET /analytics/hr`.
   - Expected: headcount drops by 1. Actual: unchanged.
   - Cause: `server/src/modules/analytics.service.js` `headcount()` (and `headcountByDepartment`, `genderAndTenure`, `averageSalary`, `attritionRisk`) ignore `users.is_active`.
4. **`%` and `_` act as wildcards in directory search** — M3-16 · Low
   - Steps: `GET /api/employees?q=%`.
   - Expected: 0 results (no name contains "%"). Actual: every employee.
   - Cause: `server/src/modules/employees.service.js` `listEmployees()` puts `q` into `ILIKE '%…%'` without escaping `%`, `_` and `\`.
5. **CSV upload over 1 MB returns 500** — M3-24 · Medium
   - Steps: as HR, upload a 1.1 MB file to `POST /api/employees/import?dryRun=true`.
   - Expected: 400/413 "File too large (max 1 MB)". Actual: 500.
   - Cause: `MulterError` (`LIMIT_FILE_SIZE`) isn't mapped in `server/src/middleware/errorHandler.js`; the limit is set in `server/src/modules/employees.routes.js:21`.
6. **CSV export allows formula injection** — M3-26 · Medium
   - Steps: register an employee named `=HYPERLINK("http://evil","x")`, then export.
   - Expected: the cell is neutralised (e.g. prefixed with `'`). Actual: written as-is, so spreadsheet apps run it.
   - Cause: `server/src/modules/employees.routes.js` (`/employees/export.csv` and the import `credentialsCsv`).
7. **No handler for dropped database connections** — observed during the M3 run · High (robustness)
   - The Supabase pooler reset idle connections (`ECONNRESET`), which surfaced as unhandled `error` events from the `pg` client.
   - In the long-running server, an unhandled `Pool` `'error'` event can crash the Node process.
   - Cause: `server/src/lib/db.js` creates `new pg.Pool(...)` with no `pool.on('error', …)` listener.
   - Side effect: vitest's dump of these unhandled errors printed the DB connection details, including the password, to the local test console.
